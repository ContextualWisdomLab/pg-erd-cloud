🚨 Severity: HIGH
💡 Vulnerability: JWT `crit` (critical) headers were not validated, violating RFC 7515. An attacker could potentially bypass security controls by including unsupported critical extensions that the application silently ignored.
🎯 Impact: High risk of security feature bypass via ignored critical parameters.
🔧 Fix: Added explicit validation to `_validate_jwt_header` in `backend/app/auth.py` to reject any JWTs with a non-empty `crit` header, since the application does not support any custom extensions. Also added checks for `crit` length and type.
✅ Verification: Ran full pytest test suite; all tests passed, including new test cases in `backend/tests/test_auth_security.py` that confirm tokens with `crit` headers are rejected with a 401 response.
