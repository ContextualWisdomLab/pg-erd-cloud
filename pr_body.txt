🚨 Severity: MEDIUM
💡 Vulnerability: User-provided string fields (such as diagram view names, table annotation schema/relation names, and API key names) lacked strict validation against control characters. They only relied on length constraints, allowing characters like null bytes, carriage returns, or terminal escape sequences to be injected.
🎯 Impact: Allowing control characters in these fields could lead to Log Injection (CRLF injection), Null Byte Injection, or terminal escape sequence injection if these inputs are subsequently logged or rendered in a terminal interface.
🔧 Fix: Enforced strict validation on Pydantic string fields (`DiagramViewCreateIn.name`, `TableAnnotationUpsertIn.schema_name`, `TableAnnotationUpsertIn.relation_name`, and `ApiKeyCreateIn.key_name`) using the regex pattern `^[^\x00-\x1F\x7F]+$`. This strictly rejects ASCII control characters and the DEL character while allowing legitimate unicode string inputs. Fields requiring multiline inputs (like `body` and `sql`) were explicitly left unchanged to prevent functionality regression.
✅ Verification: Ran `uv run pytest` and verified all tests continue to pass. The regex implementation conforms to Pydantic V2 standards.
