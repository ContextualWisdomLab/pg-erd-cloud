💡 작업 내용: Prisma 스키마 변환 시 배열 검색을 O(1) Map 조회로 개선 (성능 최적화)
🎯 이유: `exportPrisma` 생성 과정 중, edge 배열을 반복할 때마다 `node.data.columns.find` 및 배열 `.includes` 탐색을 수행하여 O(N*C*E) 병목 현상이 발생함. 이는 큰 다이어그램 내보내기 성능 저하로 이어질 수 있음.
📊 영향: 중첩 O(N) 순회 방식을 고정 시간인 O(1) Map 및 Set 조회 방식으로 교체하여 대규모 엔티티/관계 다이어그램 변환 속도(O(N*C) + O(E))를 대폭 단축함. 누락된 edge case에 대한 테스트 코드를 보완하여 커버리지 100%를 달성함.
🔬 확인: `frontend/` 디렉터리 내에서 `npm run coverage` 실행을 통해 모든 테스트 항목 통과 및 커버리지 유지(100%) 확인.
