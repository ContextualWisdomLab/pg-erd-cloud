🚨 Severity: LOW/MEDIUM (Defense in Depth)
💡 Vulnerability: User-provided string fields in Pydantic schemas (like `DiagramViewCreateIn.name`, `TableAnnotationUpsertIn.schema_name`, etc.) lacked explicit character restrictions and permitted injection of ASCII control characters (`\x00-\x1F` and `\x7F`).
🎯 Impact: While these fields don't execute code directly, control characters can trigger log injection (CRLF), terminal escape vulnerabilities, or downstream processing errors if serialized into text or logged without escaping.
🔧 Fix: Added explicit regex validation `pattern=r"^[^\x00-\x1F\x7F]+$"` to these Pydantic string fields to strictly reject control characters, hardening the application against injection.
✅ Verification: Tested against the backend test suite (`uv run pytest`), confirming schema validation passes as expected without regressions.
