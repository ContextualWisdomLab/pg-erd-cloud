## 2026-08-04 - 100% Test Coverage for Frontend Missing Branches

**Learning:** When attempting to reach 100% test coverage for frontend components, isolating branch coverage issues requires splitting large tests (like `ModalCoverage.test.tsx`) into specific component tests (like `EditEdgeModal.test.tsx` and `GroupModal.test.tsx`). Certain components like `EditEdgeModal` require explicit `window.confirm` mocking for both positive (`true`) and negative (`false`) outcomes to cover cancellation and proceed paths. Additionally, for components handling file generation or external data exports (like `prisma.ts`), edge cases such as missing edge handles must be explicitly provided in mock data to cover fallback behaviors. Furthermore, `useDialogAccessibility` requires specific tests since `useLayoutEffect` hooks only execute when DOM mounts completely, meaning `fireEvent` and `waitFor` are critical in checking element focus trapping.

**Action:** Created dedicated test files for `EditEdgeModal` and `GroupModal` to fully explore UI branches such as dialog submissions and native confirm cancelations.
