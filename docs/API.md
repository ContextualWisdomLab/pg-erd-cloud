# API Contract and Compatibility

Status date: 2026-08-09
Current lifecycle: unversioned `/api` surface `implemented_on_main`; public
share hardening `active_pr` #824; governed Forward Engineering API `planned`

OpenAPI generated by FastAPI is the route-level schema aid. This document is
the product compatibility authority for authentication, route families,
representation boundaries, and known inconsistencies.

## Authentication and request controls

- Protected APIs require `Authorization: Bearer <token>`, where the token is an
  OIDC JWT or a `pgerd_` API key.
- Unsafe `/api` methods require the HMAC CSRF header as well. Public share reads
  are GET-only and unauthenticated because the URL UUID is the capability.
- Project reads require membership; mutations generally require `editor`; share
  creation and member administration require `owner`.
- CORS uses the configured origin allowlist and explicit
  GET/POST/PUT/DELETE/OPTIONS/header lists. PUT/DELETE parity is `active_pr`
  until the current changes merge.
- Global and public-share-specific rate limits are in-memory per worker, not a
  distributed tenant quota.

Exact route handlers live under `backend/app/api/`; request models are in
`backend/app/schemas.py` and the generated OpenAPI document. Route additions or
response changes update this authority and the traceability matrix.

## Representation boundaries

### Authenticated snapshot

Authenticated project APIs may return the stored snapshot model, including
metadata available to project members. Many analyzer and snapshot responses are
currently raw dictionaries rather than named, versioned Pydantic domain
schemas. That is compatibility debt.

### Public share

The public representation is intentionally smaller. PR #824 filters listings
and details to successful snapshots, removes private error detail, and projects
snapshot roots and collection rows through path-scoped public-v1 allowlists,
and disables live-LLM execution. New links receive a configurable expiry and an
owner can delete a project-scoped link immediately. All public share routes use
the primary session for link/expiry validation so a lagging read replica cannot
continue serving a revoked bearer capability. Frontend `SharedLinkInfo` is
still a manually mirrored contract and public handlers do not declare complete
Pydantic response models; formal version negotiation and generated client
contracts remain `planned`.

### Desired model and migration plan

No current API represents an immutable editable desired model or structured
authorized migration plan. The semantic operations proposed in [TRD](TRD.md)
are `planned`; their version prefix and compatibility policy are selected in
the implementation ADR. Clients will submit model intent and identifiers, not
authoritative executable SQL.

## Current response conventions and debt

| Behavior | Current fact | Required direction |
| --- | --- | --- |
| Missing authenticated snapshot | Several endpoints return HTTP 200 plus `status="not_found"` or text markers | Versioned APIs use consistent typed errors without breaking current clients silently |
| Public missing/expired share | 404 for missing, 410 for expired | Preserve intentionally unless a versioned contract changes it |
| Connection operational failure | HTTP 200 with `ok=false` on selected test/apply paths | Document per operation; new FE jobs use typed terminal state and problem response |
| Diff project scope | Base and target are authorized independently and may belong to different projects a user can access | Make cross-project intent explicit or require same project in a versioned operation |
| Snapshot payload | Weakly typed JSON dictionaries | Introduce versioned semantic schema with tolerant readers and explicit unknown constructs |
| API prefix | Unversioned `/api` | Preserve current routes; new incompatible commercial contracts are versioned |

## Compatibility rules

- Do not remove or reinterpret a current field/route without a deprecation
  window, usage evidence, migration note, and contract tests.
- Additive public fields still receive a privacy/threat review; "additive" is
  not automatically safe for bearer links.
- Exact external SQL identifiers remain data and are never normalized merely
  to satisfy internal object naming policy.
- OpenAPI diff, SDK/consumer tests, error semantics, and rollback behavior are
  release evidence for contract changes.
